## 1. Project Abstract

This repository contains the source code, documentation, and experimental scripts developed for the Bachelor Thesis titled "Design and Implementation of a Local Full-Text Search System for Heterogeneous Documents".

The primary objective of this project is to implement `filesearch`, a high-performance, privacy-preserving desktop search engine capable of indexing and retrieving content from heterogeneous file formats (PDF, DOCX, TXT, HTML, JSON) stored on the local filesystem. The system is architected as a modular application comprising a Java-based backend CLI for orchestration and indexing, and a React-based frontend for interactive graphical retrieval.

The core retrieval logic uses an inverted index built with Apache Lucene, embedded in the backend, with document parsing and metadata extraction handled by Apache Tika. Nothing else needs to be installed or running: all data processing happens on this computer, with no external services.

> The thesis version used an external Elasticsearch node. It was replaced by embedded Lucene so the product installs as a single desktop app; the thesis-era evaluation scripts remain in the git history.

## 2. System Architecture

The project is organized into three primary modules:

*   **`tfg-filesearch` (Backend/CLI)**: A Java application that crawls folders, extracts text (Apache Tika) and keeps an embedded Lucene index with a Spanish analyzer (plurals, accents and case are ignored). It exposes a Command Line Interface (picocli) and, with `serve`, a local API for the desktop app.
*   **`tfg-filesearch-gui` (Desktop app)**: Electron + React + TypeScript. The app starts the backend itself, talks to it only from the main process with a per-session token, and shows results with highlighted matches.
*   **`scripts`**: PowerShell helpers for demos and benchmarks.

**Where data lives.** The index, statistics and logs are stored in `~/.filesearch` (override with the `FILESEARCH_HOME` environment variable). Search terms are never written to disk.

**Security model.** The backend API listens on `127.0.0.1` only, requires a random token generated by the app at every start, and refuses requests from web pages (`Origin` header) and foreign `Host` headers (DNS rebinding). The app's renderer has no network access at all; the backend stops when the app closes.

## 3. Prerequisites

To build and execute the system, the following runtime environments are required:

*   **Java Development Kit (JDK)**: Version 17 or higher.
*   **Node.js**: Version 20.19 or higher.
*   **Maven**: Version 3.8 or higher (for backend build).

## 4. Installation and Build

### 4.1 Backend Compilation
Navigate to the backend directory and build the executable JAR artifact:

```bash
cd tfg-filesearch
mvn clean package
```

The resulting artifact will be located at `target/filesearch-1.0.0-jar-with-dependencies.jar`.

### 4.2 Frontend Setup
Navigate to the frontend directory and install dependencies:

```bash
cd tfg-filesearch-gui
npm ci
```

Quality checks for the frontend:

```bash
npm run typecheck   # TypeScript
npm test            # unit tests (Vitest)
npm run build:web   # production bundle without packaging
```

## 5. Execution Guide

### 5.1 CLI Operations
Index a folder (e.g., `~/Documents`). Only new and changed files are read; deleted files are removed from the index:

```bash
java -jar tfg-filesearch/target/filesearch-1.0.0-jar-with-dependencies.jar update-index ~/Documents
```

Search:

```bash
java -jar tfg-filesearch/target/filesearch-1.0.0-jar-with-dependencies.jar search "contrato arrendamiento" --ext pdf,docx
```

| Query | Finds documents with |
| --- | --- |
| `fianza desahucio` | both words (plurals and accents ignored) |
| `"falta de pago"` | the exact phrase |
| `"arrendamiento fianza"~5` | both words at most 5 words apart |
| `fianza -arrendamiento` | "fianza" but not "arrendamiento" |
| `hipoteca \| préstamo` | either word |
| `hipotec*` | words starting with "hipotec" |

Check that text extraction for PDF/Word/RTF/ODT works and the index is readable:

```bash
java -jar tfg-filesearch/target/filesearch-1.0.0-jar-with-dependencies.jar doctor
```

Other commands: `reindex <folder>` (rebuild from scratch), `watch <folder>` (keep the index updated while running), `stats`, `benchmark`. Excluded paths, file types and size limits are in `tfg-filesearch/src/main/resources/application.yml`.

### 5.2 GUI Execution (Search)
Launch the desktop app in development mode:

```bash
cd tfg-filesearch-gui
npm run dev
```

This opens the Electron window, which starts the backend from step 4.1 (Java 17+ must be on the `PATH`; set `FILESEARCH_JAR` or `FILESEARCH_JAVA` to use other locations). From **Settings**, choose the documents folder and press **Index Now**; afterwards the app catches up with changes every time it starts. Search needs the desktop app: the plain browser preview has no backend.

## 6. Benchmarks

`scripts/benchmark.ps1` rebuilds the index of a dataset several times and runs a set of queries, keeping its index apart from yours. For query latency only, use the CLI:

```bash
java -jar tfg-filesearch/target/filesearch-1.0.0-jar-with-dependencies.jar benchmark --queries queries.txt --runs 10
```
